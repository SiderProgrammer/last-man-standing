                  How to play

                  “Verified in your browser”

                  When a match ends, this page plays the whole match again by itself. It runs the same game code the server runs, using only what was published to every player: the match seed, the rules, the seats, and every move revealed round by round.

                  Every round is hashed into a chain, and the end of that chain is the history root: one fingerprint of the entire match. The result is verified in your browser when the replay arrives at the same root and the same ranking the server announced. The server could not have invented an outcome, altered a move, or bent a dice roll without that check failing.

                  Why moves and rolls can't be bent

                  • Commit, then reveal. Locking in sends only a hash of your move and a secret salt. Moves open once everyone has locked in, and a reveal that does not match its hash is rejected.
                  • Signed by you. Your wallet grants this browser a key once, and that key signs every commit and reveal. The server can drop a move, but it cannot make one up or change one, and when it takes your commit it signs a receipt you keep.
                  • Dice nobody can see coming. Every roll (which striker a Guard blocks, how an exact tie breaks) comes from the seed mixed with every player's locked-in commitment. No one, the server included, can know the rolls before every move is locked, and nothing done at the reveal can change them.

                  Staked matches go one step further

                  Before it settles, the server archives the full transcript: every round, every signature, every grant. The escrow stores its hash along with the history root that payouts follow. Once settlement lands, this page reads the escrow, fetches the transcript by that hash, and checks it: that it is the one stored, that the seed, rules and seats are the escrow's, that every move carries its player's signature, that your own moves and receipts are all there, and that it replays to the stored root. A match then shows verified against chain.

                  If it does not, a Dispute button appears. Disputing holds the payout back 48 hours and saves your evidence to a file for the guardian, who can veto the result and refund every stake. A guardian that does nothing lets the result pay out when the 48 hours end.

                  What it does not prove

                  • That the seed was fair. In staked lobbies it comes from an on-chain randomness oracle, fixed before the first move. In practice matches the server picks it.
                  • That the moves were secret from the server if you ticked “Reveal for me if I disconnect”. The server then learns your move when you lock it in.
                  • That the other seats are not playing together.
