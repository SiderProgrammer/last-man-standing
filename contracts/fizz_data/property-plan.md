# Property Plan

> Generated by 5 specialized discovery agents, merged by the Synthesizer. 68 properties total (30 global, 38 specific).
> Priority distribution: 41 HIGH, 20 MEDIUM, 7 LOW.
> Guarantee: 61 SHOULD-HOLD, 7 EXPLORATORY.
> Categories: 30 HIGH_LEVEL, 20 STATE_TRANSITION, 11 VARIABLE_TRANSITION, 7 VALID_STATE.
> English spec with checkboxes: `PROPERTIES.md` (stable IDs, do not renumber). ~170 raw proposals merged.

Conventions used by every row:
- "Known addresses" = `actors` + `ghosts.extraAddrs` (addresses passed to unclamped handlers, deduped, cap 16). Sums of parts iterate this set; the `bridgeReceiver`, `feeRouter`, `timelock`, `safe`, `outsider` and every Terms treasury are added where a row says "creditors".
- Source of truth is `src/`; the x-ray is stale. Source checks done by the Synthesizer are listed in the last section.
- Never assert on an actor's ETH around a payable call. Receipts (a withdrawal's recipient) and protocol-side balances are fine.
- `t`, `eq`, `gte`, `lte` from `utils/PropertiesAsserts.sol`. "Must fail" = try/catch, `t(false, ...)` in the success branch.
- `Snapshots._takeSnapshot` currently stores `actor.balance`. Replace it (see Snapshot State Plan).

**Round-trip handlers**: this protocol has no ERC-4626 vault, so there is no C2 (repeated-cycle dust) or V-06 (first depositor inflation) property to wire. The equivalents are SP-20 (deposit + requestUnstake in one call earns nothing, `stakedLms_flashStake_clamped`), SP-21 (stake/unstake exactly 1:1) and SP-11 (join then cancel/abort/veto is net zero); the 1:1 wrapper makes inflation impossible, and GL-12 checks the donation case.

## Dropped, contradicted, or merged away (with reasons)

Contradicted or weakened by the current source:
- SPEC-16(b)/ADV-06 versus a worry that dispute, dismiss, dispute-by-another-seat exceeds one extension: checked in `dispute`/`dismissDispute`. Only one extension is outstanding (`disputed` flag) and dismiss removes it, so `deadline <= O + DISPUTE_EXTENSION` holds. Kept as GL-11; the "seatCount * EXT" weaker form is not needed.
- ST-19's "pending ones keep theirs" read as a SHOULD-HOLD: the source overwrites `unlockAt` on every request, as `requestUnstake` NatSpec states. Only `setCooldown` leaves pending entries alone. The "never shortens" claim is EXPLORATORY (SP-22); the rest of ST-19 is SHOULD-HOLD in SP-21.
- RD-14's clause `quorumFloor <= 10% of current LMS supply`: contradicted by `lms_burn_clamped`, since the cap is checked when the floor is set. Dropped; the rest of RD-14 is in GL-26.
- ST-18 harness note and CON-16's `getVotes` equality against `totalSupply`: `delegate(address(0))` is allowed, so the equality is restated over holders with a non-zero delegate (GL-13).
- The "`_refundAll` fast path skips LMS refund" lead (mapper note 2): `_joinWithLms` reverts `NoDiscount` unless `discount > 0`, so `total.eth == 0` implies `total.lms == 0`. No separate property; SP-11 and GL-04 still cover it.
- CON-13 / SPEC-33 exact supply identity needs `lms_burn` and finalize burns tracked; governance proposals in the harness never touch LMS, so the ghost is complete (GL-21).
- Exact LMS or ETH balance equalities in CON-05, CON-15, CON-20, CON-21, CON-24 were unsafe because unclamped `lms_transfer(address,...)` can send LMS to any contract; the `lmsDirectIn` ghost fixes that.
- `_settle` early return and `rewardPerShare` view at supply 0 were checked against the GL-14 formula; use `last` as the start when `totalSupply == 0`.

Dropped as cannot-fail or guard-restating:
- CON-14 (LMS closed system): false positives from strays to unlisted addresses; GL-21 covers supply.
- CON-25, ADV-25, VS-06 as a global (held ETH == ghost): the ghost is defined from the same balance deltas, so it cannot fail. Per-call checks are in SP-17 and SP-18. No property on `bridge_handleOnHeldEth_clamped` (trust assumption).
- ADV-34 (drain and reenter): the empty-state case of GL-01/02/03/12 with identical assertions.
- ST-30 (per-match credited ghost): restates SP-08 and SP-11.
- RD-13 (withdrawFor dust floor) and RT-13 (zero input): restate `BelowMinimumWithdrawal`, `ZeroAmount`, `NoDiscount`; dust reachability is in SP-13.
- VS-01(b) (`paused() == now < pausedUntil`): the definition of `paused()`.
- ST-14 / ADV-03 / SPEC-18(a) "create, join, lock, settle are refused while paused": restates `whenNotPaused`; only the "exits never refused" half is kept (SP-14).
- ST-26 parameter-validity clauses (fee <= MAX, seats, windows, schedule sums to 10000): each is enforced by the setter that writes it; only history, set-once and the delay-versus-lifetime relation are kept (GL-30).
- VS-02 (`matchNonce == matchIds.length`): a harness sync check, not a protocol property.
- SPEC-13 `maxEpochFees` ghost: folded into SP-10, which compares against the recomputed fee.
- RT-06 global `slmsDeposited - slmsClaimed` ghost: initial stakes are deposited in setup; the per-call exactness is SP-21 and the aggregate is GL-12/13.
